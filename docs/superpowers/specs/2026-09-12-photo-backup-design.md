# 메모요 사진 백업·복원 2단계 — T-260829-024

2026-09-12 사용자 아테나 Codex 직접 승인: “좋아, 메모요 사진 백업·복원 작업 진행해.”
1단계 PR #137 위에서 구현한다. 파일 내보내기와 Drive 모두 같은 ZIP을 사용한다.

## 형식과 호환

- ZIP 루트 `memos.json`: 기존 메모 JSON 목록 및 `images` 파일명 목록 그대로.
- `attachments/<파일명>`: 백업 대상 메모가 참조하는 사진 실물만, 공유 참조는 한 번 저장.
- 백업 화면의 기존 원칙대로 활성 메모만 내보낸다. 사진 누락·읽기 실패는 백업 실패로 알리고 불완전한 백업을 성공 처리하지 않는다.
- 복원은 ZIP과 기존 JSON 모두 지원한다. 예전 JSON의 사진 파일명은 보존하지만 없는 실물을 만들어낼 수는 없다.
- Drive 목록과 최근 7개 보관은 JSON·ZIP을 함께 처리한다. 기존 Drive 인증 범위는 유지한다.

## 복원과 파일 수명

- 파일 해석·경로·크기·CRC·사진 참조를 검증한 후에만 로컬 데이터를 변경한다.
- 기존 id/updatedAt 병합 규칙을 유지한다. 채택된 incoming 메모의 사진만 저장하며 새 UUID 파일명으로 연결한다. 같은 이름의 기존 사진은 덮어쓰지 않는다.
- 저장 실패 시 이번에 생성한 파일만 제거하고 기존 메모와 이전 undo snapshot을 보존한다. 무참조 ZIP 사진은 설치하지 않는다.
- 이전 메모의 사진은 undo snapshot이 참조하는 동안 고아 정리·영구삭제에서 보호한다. undo 저장이 성공하면 더 이상 참조하지 않는 가져온 사진을 제거한다.
- ZIP은 메모 JSON 16 MiB, 사진 개당 8 MiB, 전체 입력·압축 해제 128 MiB, 항목 4096개로 제한한다. 해제 도중에도 출력 크기를 제한하며 경로 이탈·중복 항목·링크·암호화 항목을 거부한다.
- ZIP과 파일/Drive 입출력에 동일 코덱을 사용한다. 파일 저장·읽기 중 화면의 다른 백업/복원 버튼은 비활성화한다.

## 검증과 범위

실제 임시 파일로 사진 포함 왕복, 파일명 충돌, 중복 import, 오래된 메모 제외, 누락·손상 ZIP, JSON 호환, 저장 실패 rollback, undo와 사진 수명을 검증한다. Drive는 모의 HTTP/API로 ZIP 바이트·MIME·목록·회전을 검증하고 화면 버튼·한국어/영어 문구도 검증한다.

버전·스토어 제출·서명·실기기 설치·실제 사용자 Drive 데이터 변경·머지는 범위 밖이다. 산출물은 코드·테스트·PR 1개. archive는 기존 lock의 4.0.9를 직접 의존성으로 고정한다([패키지 문서](https://pub.dev/packages/archive/versions/4.0.9)); 해당 버전 decoder의 CRC 검증이 비활성이므로 읽은 바이트의 CRC를 직접 확인한다.
