## 1. 시뮬레이터 smoke (자동화 가능 — `flutter run -d <sim>` + 사람 클릭)

### 1.1 로컬 메모 CRUD (회귀 가드)

1. FAB → 메모 입력 "QA 메모 1" → 저장 → 목록 상단 진입
2. 메모 탭 → 본문 "QA 메모 1 수정" 변경 → 저장 → 목록 동기화 확인
3. 스와이프 → 즐겨찾기 토글 → 목록 최상단으로 이동
4. 스와이프 → 삭제 → 다이얼로그 "삭제" → 사라짐 + **SnackBar "메모를 삭제했습니다 / 실행 취소"** 노출 (4초)
5. SnackBar 의 "실행 취소" 탭 → 메모 같은 자리에 재등장 (단계 1 의 즐겨찾기 그룹 위치 보존)
6. 앱 강제 종료 후 재실행 → 메모 영속 (`SharedPreferences`)

### 1.2 편집 모드 벌크 삭제 + UNDO

1. 목록에서 임의 5개 메모 생성 (즐겨찾기 2개 + 일반 3개)
2. 편집 모드 진입 → "전체선택" 탭 → 5개 모두 체크
3. 삭제 → 다이얼로그 "선택한 5개 메모를 삭제하시겠습니까?" → "삭제"
4. 5개 모두 사라짐 + **SnackBar "메모를 삭제했습니다 / 실행 취소"**
5. "실행 취소" 탭 → 5개 모두 **원래 인덱스** + **즐겨찾기 그룹 순서** 복원
6. 다시 편집 모드 진입 → 3개 선택 + 삭제 → SnackBar 무시 (4초 dismiss 대기) → 3개 영구 삭제 확인 (재시작 후 안 돌아옴)

### 1.3 메모 공유

1. 임의 메모 탭 → 편집 화면 진입
2. AppBar 오른쪽 공유 IconButton 탭
3. 시스템 share sheet 노출 (iOS = UIActivityViewController / Android = chooser)
4. share sheet "취소" → 편집 화면 복귀, 본문 변경 없음
5. 공유 대상 X (전송 없이 dismiss) — share sheet 외부 발신 없는지 확인

### 1.4 백업 / 가져오기 (mock 경로)

> 시뮬레이터에서 Google OAuth 동의는 실 동작 X — `DriveBackupService` 가 mock 반환하도록 분기되거나, share sheet 기반 file picker 만 검증.

1. overflow 메뉴 → "메모 내보내기" → share sheet → "파일에 저장" → 임의 로컬 위치
2. overflow 메뉴 → "메모 가져오기" → 직전 저장 파일 선택 → "메모 N개 가져왔습니다" SnackBar
3. SnackBar 의 "되돌리기" 탭 → 가져오기 이전 상태 복원
4. overflow 메뉴 → "Drive 백업" → 시뮬레이터에서는 OAuth 미연결 → `DriveBackupPermissionDenied` 분기 SnackBar 노출 (실 OAuth 는 §2.1 에서)

## 2. 실기기 smoke (사람 손 필수 — 외부 OAuth / share sheet)

### 2.1 iPhone 17 — Drive 백업 round-trip

1. TestFlight 빌드 설치 → 첫 실행 → 메모 3개 생성
2. overflow 메뉴 → "Drive 백업" 첫 탭
3. Google 계정 선택 시트 → 강대종 본인 계정 선택
4. **OAuth 동의 시트** 노출 — "Memoyo 가 Google Drive 의 자체 파일 보기 권한 (`drive.file`) 을 요청합니다" → 허용
5. 진행 인디케이터 → SnackBar "Drive 에 저장됐어요 / Memoyo 폴더 열기"
6. "Memoyo 폴더 열기" 탭 → Google Drive 앱 또는 브라우저로 `Memoyo` 폴더 진입 → `memoyo-backup-<timestamp>.json` 파일 1건 확인
7. 메모 1개 더 생성 → "Drive 백업" 재탭 → 인디케이터 없이 즉시 SnackBar (OAuth 캐시)
8. `Memoyo` 폴더에 2번째 파일 추가 확인 (직전 파일 그대로 유지, 회전 임계 7 미달)

### 2.2 iPhone 17 — 백업 8회 회전

1. 위 2.1 상태에서 백업 6회 추가 탭 (총 8건)
2. Drive 폴더에서 7건만 유지 (가장 오래된 1건 자동 삭제) 확인
3. SnackBar 가 매번 정상 동작, 실패 0

### 2.3 iPhone 17 — restore 검증 (앱 데이터 클리어)

1. 메모요 앱 강제 종료 → iOS 설정 → 메모요 → "앱 데이터 삭제" (또는 앱 삭제 후 재설치)
2. 메모요 재실행 → 빈 메모 목록 확인
3. overflow 메뉴 → "메모 가져오기" → 시스템 file picker → "탐색" → Google Drive 앱 → `Memoyo` 폴더 → 최신 백업 파일 선택
4. "메모 N개 가져왔습니다 / 되돌리기" SnackBar
5. 직전 백업 메모 전부 복원 확인 (즐겨찾기 그룹 순서 포함)

> **§2.3 의 가져오기 1버튼화** (PR #24 picker) 도 시뮬레이터 §1.4 와 동일하게 실기기에서 OAuth → Drive 폴더 자동 list → 1버튼 가져오기 검증. share sheet picker 와 1버튼 picker 두 흐름 모두 PASS 필요.

### 2.4 Galaxy S24 — OAuth 폰 데이터 클리어 회귀

1. Play Internal 빌드 설치 → 첫 실행 → 메모 1개 생성 → "Drive 백업"
2. OAuth 동의 → 백업 성공 확인
3. 안드로이드 설정 → 메모요 → "저장공간 및 캐시" → "저장공간 지우기" → "캐시 지우기" 둘 다
4. 메모요 재실행 → 빈 목록 → "Drive 백업" 재시도
5. **시나리오 A — 재인증 정상**: OAuth 동의 시트 재노출 → 허용 → 백업 성공
6. **시나리오 B — stale 토큰**: PermissionDenied SnackBar 노출 시 → 안드로이드 설정 → Google 계정 → 보안 → 타사 앱 → 메모요 권한 제거 → 재시도 → 시나리오 A 로 회귀

> [[T-260520-14]] 의 OAuth 동의 시트 stale 사고가 이 시나리오의 출처.

### 2.5 양 폰 — 메모 공유 실 share sheet

1. 메모 1건 탭 → 편집 화면 → 공유 IconButton 탭
2. iPhone: AirDrop / Messages / Mail / 카카오톡 → "Messages" 선택 → 본인 번호로 전송 → 수신 확인
3. Galaxy: 카카오톡 / Gmail / Messages → "카카오톡" 선택 → 본인 채팅으로 전송 → 수신 확인
4. 본문 내용 + 줄바꿈 정확히 보존 확인 (`\n` 손실 0)

### 2.6 양 폰 — 시스템 다크모드 토글 회귀

1. 시스템 설정 → 라이트모드 → 메모요 진입 → 메모 작성/목록/편집 → 시각적 깨짐 0
2. 시스템 설정 → 다크모드 → 메모요 복귀 → 즉시 다크 적용 확인 (앱 재시작 X)
3. 즐겨찾기 / 편집 모드 / 삭제 다이얼로그 / SnackBar 다크 모드 색상 가독성 확인
