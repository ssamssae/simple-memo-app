## 1. (1) 구글 드라이브 단일 버튼화

### 1.1 정책 갱신 — share sheet 자유 선택 → Drive 1버튼

직전 spec [`docs/superpowers/specs/2026-05-18-memo-export-import-design.md`](../superpowers/specs/2026-05-18-memo-export-import-design.md) line 37 의 다음 정책:

> "사용자는 share sheet 에서 자유롭게 저장처 선택 (메일·AirDrop·iCloud Drive·Google Drive·카카오톡 등). 앱은 어느 저장처로 갔는지 추적하지 않는다."

→ **deprecated (1.0.7)**. 새 정책:

> "사용자가 Google Drive 1회 sign-in 후 모든 export/import 는 Drive 의 `appDataFolder` 1탭. 다른 저장처 선택지 노출 0."

**갱신 사유** (telegram msg 19841, form님 메모리 [[project_memoyo_auto_sync_dropped_2026_05_18]] 보강):
- **기기변경 iOS↔Android CS 0**: 1.0.5+ 사용자가 가장 많이 묻는 CS = "안드로이드에서 만든 메모를 아이폰으로 못 옮긴다". share sheet 자유 선택은 사용자가 어느 저장처에 저장했는지 잊어버리면 import 시 못 찾는 함정. Drive 단일 채널은 "내 Drive 계정 = SoT" 명확.
- **동시 사용 conflict CS 사유**: 자동 백업은 다중 기기 동시 사용 시 최신 충돌 발생 → 사용자 수동 export/import 로 명시 의도 유지.
- **share sheet 자유 선택은 단일 메모 공유 (항목 3) 에는 그대로 유지** — 백업 vs 공유 분리.

### 1.3 Drive 백업 폴더 결정 — `appDataFolder` vs 일반 폴더

| 옵션 | 가시성 | 데이터 안전 | 다른 앱 공유 |
|------|--------|-------------|--------------|
| **`appDataFolder` (권장)** | 사용자가 Drive 웹 UI 에서 안 보임 | 앱 삭제 시에도 유지 | X (앱 본인만 read/write) |
| 일반 폴더 `메모요 백업/` | 사용자가 Drive 웹 UI 에서 보임 | 사용자가 실수로 삭제 가능 | O (사용자가 zip 으로 다운로드 등) |

**권장**: `appDataFolder`. 사용자가 Drive 정리하다 실수로 삭제할 위험 0. 다만 사용자가 "이 백업 파일을 다른 곳에 보내고 싶다" 의도가 있으면 (예: 친구에게 메모 공유) 일반 폴더가 유리. **[[form님 결정 펜딩]]** — 메모요 사용자 페르소나 (개인 메모) 보면 `appDataFolder` 가 적합.

### 1.4 UX flow

**Export (메모 백업)**:
1. AppBar overflow → "메모 백업" 1탭 (기존 "메모 내보내기" 라벨 변경)
2. Drive sign-in 안 됐으면: sign-in 화면 1회 노출 → 형님 Google 계정 선택 + scope 동의 (drive.appdata)
3. sign-in 완료 후: 현재 메모 전체 JSON 직렬화 → Drive `appDataFolder` 에 `memoyo-backup-YYYYMMDD-HHMMSS.json` 업로드
4. 진행 중 `CircularProgressIndicator` overlay
5. 완료 SnackBar "Drive 에 백업했습니다 (N개 메모)"
6. 실패 (Drive 권한 거부 / 네트워크 / quota) — 명확한 한국어 메시지 토스트

**Import (메모 복구)**:
1. AppBar overflow → "메모 복구" 1탭
2. Drive sign-in 안 됐으면: sign-in 화면 1회 노출
3. sign-in 완료 후: Drive `appDataFolder` 의 `memoyo-backup-*.json` 리스트 fetch
4. 백업 파일이 0개: SnackBar "백업이 없습니다. 먼저 다른 기기에서 메모 백업을 해주세요."
5. 백업 파일이 1개: 자동 선택 → 다음 단계
6. 백업 파일이 2개 이상: 리스트 다이얼로그 (파일명 + 생성일시 + 메모 N개 정보 — fetch 시 파일 메타에서 추출) → 1개 선택
7. 선택 후 다운로드 → parse → silent merge (1.0.6 흐름 그대로) → 스냅샷 저장 → SnackBar "메모 N개 가져왔습니다 [되돌리기]"

### 1.5 Sign-out / 계정 전환

### 1.6 Drive 미설치 / 미사용 / 미지원 케이스

- **Drive 앱 미설치**: google_sign_in 은 Google Play Services / 브라우저 fallback 로 작동 → 별 처리 X
- **사용자가 sign-in 거부**: SnackBar "Drive 로그인이 필요합니다. 메뉴에서 다시 시도해주세요." + 취소 동작 부드럽게 (앱 종료 X)

### 2.4 30일 purge — 트리거 위치

`lib/services/memo_storage.dart` 에 정적 메서드 추가:
```dart
static Future<int> purgeExpiredTrash() async {
  final all = await loadMemos();
  final cutoff = DateTime.now().subtract(const Duration(days: 30));
  final survivors = all.where((m) {
    if (m.deletedAt == null) return true;
    return m.deletedAt!.isAfter(cutoff);
  }).toList();
  final purged = all.length - survivors.length;
  if (purged > 0) await saveMemos(survivors);
  return purged;
}
```

**호출 위치 2 곳**:
1. **Cold start**: `MemoListScreen._loadMemos()` 진입 시 `MemoStorage.purgeExpiredTrash()` await
2. **App resume**: `MemoListScreen` 을 `WidgetsBindingObserver` 로 mixin 추가 + `didChangeAppLifecycleState(AppLifecycleState.resumed)` 에서 purge + `_loadMemos()` 재호출

**근거**: 사용자가 앱 안 켠 채로 30일 지나면 cold start 1회로 일괄 purge. 앱 켜있는 동안 자정 넘어가도 별 처리 X (사용자가 휴지통 화면에 진입할 때 X일 후 영구삭제 표시는 timer 없이 build 시점 계산).

### 2.7 `_deleteMemo` / `_deleteSelected` 변경

```dart
Future<void> _deleteMemo(String memoId) async {
  final index = _memos.indexWhere((m) => m.id == memoId);
  if (index == -1) return;
  final memo = _memos[index];

  final confirmed = await showDialog<bool>(/* 기존 다이얼로그 */);
  if (confirmed != true || !mounted) return;

  setState(() {

    _unfavoriteAnchors.remove(memoId);

void _restoreFromTrash(String memoId) {
  final index = _memos.indexWhere((m) => m.id == memoId);
  if (index == -1) return;
  setState(() {
    _memos[index] = _memos[index].copyWith(deletedAt: null);
  });
  _saveMemos();
}
```

`_deleteSelected` 동일 패턴 — 일괄 마킹 + 5초 UNDO ("메모 N개 휴지통으로 이동").

**중요**: `_memos` 가 휴지통 항목도 포함. 일반 리스트 build 시 `where((m) => m.deletedAt == null)` 필터 필수.

```diff
 Widget build(BuildContext context) {
-  final favorites = _memos.where((m) => m.isFavorite).toList();
-  final normals = _memos.where((m) => !m.isFavorite).toList();
+  final active = _memos.where((m) => m.deletedAt == null);
+  final favorites = active.where((m) => m.isFavorite).toList();
+  final normals = active.where((m) => !m.isFavorite).toList();
```

### 2.8 마이그레이션 안전

- **기존 1.0.6 이하 사용자 메모**: `deletedAt` 필드 없음 → fromJson 에서 null 으로 자동 마이그레이션. 데이터 손실 0.
- **1.0.7 이전 export JSON 파일을 1.0.7 에서 import**: deletedAt 필드 없는 entry → null. 정상.
- **1.0.7 에서 export JSON 을 1.0.6 으로 import** (downgrade): 1.0.6 의 fromJson 은 deletedAt 키 무시 → 휴지통 항목까지 1.0.6 일반 리스트에 노출됨. **[[알려진 한계]]** — 사용자가 의도적으로 downgrade 하지 않으면 발생 0. 1.0.7 release notes 에 "다운그레이드 시 휴지통 메모가 일반 리스트로 보일 수 있음" 1줄 명시.

### 2.9 edge cases

| 케이스 | 처리 |
|--------|------|
| UNDO 스낵바 떴는데 사용자가 즉시 다른 메모 삭제 | 새 스낵바가 기존 대체 (Material 디폴트) — 직전 메모는 그냥 휴지통에 그대로 |
| UNDO 탭했는데 timing 문제로 이미 5초 경과 | 5초 경과 후 SnackBar 자동 dismiss 되므로 SnackBarAction onPressed 호출 0 — 안전 |
| 30일 경과 직전에 사용자가 휴지통 진입 → 복구 시도 → purge 동시 발생 | _loadMemos() 가 purge 후 호출 — 동시 충돌 없음 (Dart single-threaded) |
| 즐겨찾기 메모 삭제 후 복구 시 위치 | `_unfavoriteAnchors` 가 이미 클리어됨 → 즐겨찾기 그룹 끝에 복귀. **[[결정 펜딩]]**: 정확한 위치 복원이 필요한지 vs 끝 복귀 OK 인지 |
| Drive 백업 JSON 에 휴지통 메모 포함 여부 | **포함** (deletedAt 필드 그대로) — 백업/복구 시 휴지통 상태도 유지 |
| 휴지통 비어있는데 메뉴 "휴지통" 탭 | 진입 OK + 빈 상태 화면 |

```dart
Future<void> _shareMemo() async {
  final content = _contentController.text.trim();
  if (content.isEmpty) return;
  try {
    final box = context.findRenderObject() as RenderBox?;
    final origin = box != null
        ? box.localToGlobal(Offset.zero) & box.size
        : const Rect.fromLTWH(0, 0, 100, 100);
    await Share.share(
      content,
      subject: content.split('\n').first.trim(),
      sharePositionOrigin: origin,
    );
  } catch (e) {
    if (!mounted) return;
    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(content: Text('공유 실패: $e')),
    );
  }
}
```

### 3.4 iOS / Android 차이

- **iOS**: `Share.share` → UIActivityViewController. iPad popover 위치 = sharePositionOrigin. text 만 (file 없음) 이라 `Share.share` (X 없는 single arg) 그대로.
- **Android**: `Share.share` → Intent.ACTION_SEND chooser. text/plain MIME.
- **subject**: 메일 클라이언트가 제목으로 사용 — 메모 첫 줄 (firstLine).

### 3.5 edge cases

| 케이스 | 처리 |
|--------|------|
| 메모 내용 1자만 | enable (1자 share OK) |
| 메모 5000자 | share_plus 가 처리 — 시스템 share sheet 가 alert (예: 카톡 글자 수 제한) |
