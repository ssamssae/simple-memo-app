## 0. 배경

2026-05-15 competitor 분석은 메모요 1.0.5/1.0.6 후보로 세 가지를 남겼다.

1. PIN/생체인증 잠금
2. 사용자 클라우드 옵션
3. 홈 위젯

그 뒤 메모요는 1.0.7+28까지 진행됐고, Drive 1버튼 백업/복원, 휴지통 30일, 삭제 되돌리기, 메모 공유가 들어갔다. 따라서 이 문서는 과거 후보를 그대로 1.0.5/1.0.6에 넣는 문서가 아니라, 현재 제품 상태에 맞춰 남은 후보를 다시 정렬한다.

## 1. 결정 요약

| 순위 | 후보 | 권장 배치 | 결정 |
|---:|---|---|---|
| 1 | PIN/생체인증 잠금 | 1.0.x 다음 기능 후보 | 채택 후보 |
| 2 | 홈 위젯 | 1.1.x 이후 또는 사용자 요청 누적 시 | 보류 |
| 3 | 추가 클라우드 옵션 | 1.2.x sync/data track | 1.0.x 제외 |

**추천 1픽**: PIN/생체인증 잠금.

이유:

- 메모요의 핵심 포지션은 "계정 0, 서버 0, 로컬 저장"이다. 잠금은 이 포지션을 훼손하지 않고 privacy-first 메시지를 강화한다.
- Standard Notes 의 privacy-first 메시지와 에스메모의 비밀 메모 기능을 동시에 견제한다.
- Drive 백업은 이미 1.0.7에서 들어갔으므로, 클라우드 후보를 더 늘리는 것보다 로컬 보안감을 보강하는 쪽이 더 선명하다.
- 홈 위젯은 노출/편의성 가치는 크지만 iOS/Android 플랫폼별 구현, 잠금 화면 노출 위험, 앱의 미니멀 톤 훼손 가능성이 있다.

## 2. 후보별 판단

### 2.1 PIN/생체인증 잠금

**목표**: 앱 진입 시 사용자가 설정한 PIN 또는 기기 생체인증으로 메모 목록 접근을 막는다.

**사용자 가치**:

- 민감한 임시 메모를 로컬에 적는 사용자의 불안을 줄인다.
- "클라우드 안 쓰는 메모장" 메시지를 "내 폰 안에서도 잠글 수 있는 메모장"으로 확장한다.
- 비밀 메모를 따로 분리하지 않아도 전체 앱 잠금으로 단순하게 해결한다.

**권장 범위**:

- 설정 화면 `앱 잠금` 토글.
- 첫 활성화 때 4~6자리 PIN 설정.
- 가능하면 `local_auth` 생체인증을 PIN 위에 얹는다.
- 앱 cold start 또는 일정 시간 백그라운드 후 재진입 시 잠금.
- PIN 분실 시 복구 없음. 대신 "PIN을 잊으면 앱 데이터 초기화 필요"를 설정 전에 명시한다.

**비범위**:

- 메모별 잠금.
- 서버 복구, 이메일 복구, 마스터키.
- 백업 파일 암호화. Drive 백업 암호화는 별도 데이터 보안 트랙이다.

**주의점**:

- PIN은 `SharedPreferences` 평문 저장 금지. 최소한 salt+hash 또는 플랫폼 secure storage 사용.
- 생체인증만 단독으로 쓰면 기기 설정 변화/실패 케이스가 있으므로 PIN fallback 필요.
- 앱 잠금은 보안 기능처럼 보이므로 실패 UX와 복구 불가 안내를 Help/FAQ에 같이 넣어야 한다.

### 2.2 사용자 클라우드 옵션

**현재 상태**: 1.0.7에서 Google Drive 1버튼 백업/복원이 이미 들어갔다.

**판단**:

- 과거 후보의 핵심 의도였던 "서버 0으로 sync 욕구 일부 흡수"는 이미 충족됐다.
- iCloud Drive, Dropbox, OneDrive 같은 선택지를 추가하면 사용자 선택지와 CS가 늘어난다.
- 자동 동기화는 백업/복원이 아니라 데이터 일관성 기능이다. 충돌 해결, tombstone, pull/push 정책이 필요하다.

**결론**:

- 1.0.x에서는 추가 클라우드 옵션을 넣지 않는다.
- 다기기 동기화는 기존 `docs/research/2026-05-21-memoyo-1.1.x-multidevice-sync-research.md` 와 `docs/research/2026-05-21-memoyo-decision-brief.md` 를 기반으로 1.2.x 데이터 트랙에서 다룬다.

### 2.3 홈 위젯

**목표**: 홈 화면에서 최근 메모 또는 빠른 작성 진입점을 제공한다.

**사용자 가치**:

- 에스메모의 강한 USP인 위젯 편의성을 견제한다.
- 메모 앱 사용 빈도를 높이고 "빠르게 적기" 포지션과도 맞는다.

**보류 이유**:

- iOS/Android 구현이 갈라진다. iOS WidgetKit, Android AppWidget/Glance 모두 별도 유지보수 표면이다.
- 메모 내용을 위젯에 노출하면 잠금 후보와 충돌한다. 잠금이 켜진 사용자는 위젯에 내용이 노출되면 안 된다.
- 단순 빠른 작성 버튼만 제공하면 구현은 쉬워지지만 에스메모 위젯 견제 효과는 약하다.

**권장 재평가 조건**:

- 사용자 리뷰/문의에서 "위젯" 요구가 반복된다.
- 앱 잠금 spec이 먼저 정리되어 위젯의 내용 노출 정책을 명확히 할 수 있다.
- 1.1.0 Usage Pack 이후 앱의 설정/도움말 구조가 충분히 자리 잡는다.

## 3. 다음 액션

1. PIN/생체인증 잠금을 다음 1.0.x 제품 후보로 둔다.
2. 구현 전 별도 spec을 만든다. 최소 결정사항은 다음 네 가지다.
   - PIN 자리수: 4자리 vs 6자리
   - 생체인증 사용 조건: optional overlay vs 필수
   - 재잠금 타이밍: cold start만 vs background N분 후
   - 데이터 초기화 UX: PIN 분실 시 어떤 문구와 버튼을 둘지
3. 홈 위젯은 앱 잠금 이후 재평가한다.
4. 추가 클라우드 옵션은 1.0.x 백로그에서 빼고 sync/data track으로 유지한다.

- 이 문서는 자동 동기화 결정을 내리지 않는다.
- 이 문서는 홈 위젯을 폐기하지 않는다. 단, 현재 릴리스 우선순위에서 내린다.
