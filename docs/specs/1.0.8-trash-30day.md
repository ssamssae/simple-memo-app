## §2 데이터 모델

### 2.1 Memo 모델 변경

현재 (lib/models/memo.dart):
```dart
class Memo {
  final String id;
  String content;
  bool isFavorite;
  final DateTime createdAt;
  DateTime updatedAt;
  // ...
}
```

변경:
```dart
class Memo {
  final String id;
  String content;
  bool isFavorite;
  final DateTime createdAt;
  DateTime updatedAt;
  DateTime? deletedAt; // NEW — null = 활성, non-null = 휴지통
  // ...
}
```

### 2.2 toJson / fromJson

```dart
Map<String, dynamic> toJson() => {
  'id': id,
  'content': content,
  'isFavorite': isFavorite,
  'createdAt': createdAt.toIso8601String(),
  'updatedAt': updatedAt.toIso8601String(),
  if (deletedAt != null) 'deletedAt': deletedAt!.toIso8601String(),
};

factory Memo.fromJson(Map<String, dynamic> json) {
  // ... 기존 필드들 ...
  return Memo(
    // ...
    deletedAt: json['deletedAt'] != null
        ? DateTime.tryParse(json['deletedAt'] as String)
        : null,
  );
}
```

**디자인 결정**:
- 디폴트 값 = `null` → 기존 메모 (deletedAt 키 없음) 는 자동으로 활성으로 해석
- JSON 직렬화 시 `deletedAt == null` 이면 키 자체 omit → 기존 백업/내보내기 JSON 호환성 최대 (이전 버전 클라이언트가 키 모름 → 무시)

### 2.3 copyWith 갱신

```dart
Memo copyWith({
  String? content,
  bool? isFavorite,
  DateTime? updatedAt,
  DateTime? deletedAt,
  bool clearDeletedAt = false, // NEW — restore 시 명시적 null 화
}) {
  return Memo(
    id: id,
    content: content ?? this.content,
    isFavorite: isFavorite ?? this.isFavorite,
    createdAt: createdAt,
    updatedAt: updatedAt ?? this.updatedAt,
    deletedAt: clearDeletedAt ? null : (deletedAt ?? this.deletedAt),
  );
}
```

**주의**: Dart 의 nullable optional 파라미터 패턴 — `null` 을 명시적으로 전달하면 "값 없음" 으로 해석되어 기존 값 유지. restore 동작은 `clearDeletedAt: true` 별 플래그 필요.

### 2.4 영속 layer 마이그레이션

현재 영속 = `SharedPreferences` 단일 key `'memos'` 에 `Memo.encodeList` JSON 문자열 박음.

마이그레이션 plan:
- **A안 (추천)**: schema bump 없음, **JSON 키 누락 = null 디폴트** 로 자연스러운 마이그. `fromJson` 의 `json['deletedAt'] != null` 가드 가 자동 처리.
- **B안 (비추)**: 별 key `'trash'` 분리. 마이그 코드 + 휴지통 화면 진입 시 join 비용. 휴지통 사용 빈도 < 5% 라 join 비용 단일 key 보다 크면 안 함.

**결정**: A안.

### 2.5 기존 사용자 데이터 보존 검증

- 1.0.7 → 1.0.8 업그레이드 후 첫 로드: 기존 메모 N개가 모두 `deletedAt: null` (활성) 으로 로드. 휴지통은 비어있음.
- Memo.decodeList 의 `whereType<Map<String, dynamic>>` + Memo.fromJson default 가드가 깨진 JSON 도 빈 list 반환 (PR #27 이미 커버).

## §3 GC 정책 (30일 영구 삭제)

### 3.1 GC trigger 시점 — 옵션

| 옵션 | 트리거 | 비용 | risk |
|---|---|---|---|
| **A** | 앱 cold start (initState) | 단순, 신뢰 | 앱 닫고 30일+ 안 켜면 GC 안 됨 (수용 OK) |
| **B** | background → foreground (AppLifecycle resumed) | 추가 GC 기회 | 잦은 백포 전환 시 IO 부담 |
| **C** | 메모 리스트 로드 시점 (`_loadMemos`) | 가장 자연 | 위와 동일 |
| **D** | 별 isolate / WorkManager / iOS bg-task | 진짜 백그라운드 | 복잡도 폭발 — iOS bg-task 제약 / Android Doze 모드 / 배터리 영향 |

**추천**: **A + C 묶음**. cold start 1회 + 메모 리스트 진입 시 1회. 양쪽 다 idempotent, 비용 거의 0 (memos.length × O(1) timestamp 비교).

D안은 1.0.8 비추 — 본 기능 가치 < 복잡도.

### 3.2 GC 알고리즘

```dart
class MemoStorage {
  static Future<List<Memo>> loadMemos() async {
    final all = await _rawLoad();
    final now = DateTime.now();
    final survived = <Memo>[];
    final purged = <Memo>[];
    for (final m in all) {
      if (m.deletedAt != null &&
          now.difference(m.deletedAt!).inDays > 30) {
        purged.add(m);
      } else {
        survived.add(m);
      }
    }
    if (purged.isNotEmpty) {
      await _saveRaw(survived); // 영구 삭제 영속화
    }
    return survived;
  }
}
```

### 3.3 30일 정확도

- 일 단위 = `now.difference(deletedAt).inDays > 30`
- 자정 boundary X — 삭제 시점 + 30일 = 영구 삭제 시점 (분 단위 정확)
- 사용자 입장에서는 "30일" 이 정확히 30 × 24h 라 직관과 일치

### 3.4 부분 실패 시 안전

- `_saveRaw` 실패 시 = 기존 SharedPreferences 미변경 → 다음 cold start 가 재시도. silent retry 자연스러움
- network/저장공간 에러 = SharedPreferences 영역 아님 (디스크 IO 단순 — iOS NSUserDefaults / Android SharedPreferences XML). 실패 빈도 ≪ 1% 가정 OK

### 3.5 GC 호출 결과 사용자 surface 여부

- **추천**: surface X. 휴지통 cleanup 은 사용자 인지 0 의 자동화 가치 (iOS Photos 모델). 삭제 알림 = 노이즈
- 예외: 휴지통 화면 진입 시 "마지막 cleanup: ${X일 전}" 작은 footnote = 디버깅 신뢰 — 1.0.9 후보

## §4 휴지통 화면 UX

### 4.1 진입 경로

현재 overflow PopupMenu (memo_list_screen.dart) 항목:
- "Drive 에 백업"
- "메모 가져오기"
- "가져오기 되돌리기" (조건부)

추가:
- "휴지통" (휴지통 entry > 0 일 때만 표시 — 빈 휴지통은 메뉴 entry 자체 숨김)

**결정**: overflow 메뉴 단일. 편집 모드 진입 동선은 1.0.8 비추 (휴지통 = read-mostly 화면).

### 4.2 휴지통 화면 레이아웃

```
┌─────────────────────────┐
│ ← 휴지통 (N개)    [⋮]  │ ← AppBar (뒤로가기 + 카운터 + overflow)
├─────────────────────────┤
│ ☐ 메모 첫 줄...         │
│   삭제: 3일 전          │ ← deletedAt humanize ("3일 전")
│   남은 일수: 27일       │ ← 30 - elapsed
├─────────────────────────┤
│ ☐ 또다른 메모 첫줄...   │
│   삭제: 28일 전         │
│   남은 일수: 2일 ⚠️     │ ← 3일 이하 경고색
├─────────────────────────┤
│ ...                     │
└─────────────────────────┘
[ 일괄 복원 ] [ 일괄 영구삭제 ] ← 선택 모드 진입 시 하단 bar
```

### 4.3 entry 카드 디자인

- **메모 첫 줄**: `Memo.firstLine` (기존 getter 재사용)
- **deletedAt humanize**: "방금 / N분 전 / N시간 전 / N일 전". 1.0.7 의 시각 표시와 일관성
- **남은 일수 카운트다운**: `30 - now.difference(deletedAt).inDays`. 3일 이하 = `Colors.amber.shade300` 경고색
- **체크박스**: 선택 모드 진입 시 표시 (편집 모드와 유사 패턴)

### 4.4 액션

| 액션 | 트리거 | 동작 |
|---|---|---|
| 단건 복원 | entry 스와이프 → "복원" 버튼 | memo.copyWith(clearDeletedAt: true) → 활성으로 |
| 단건 영구삭제 | entry 스와이프 → "영구삭제" 버튼 | memos.removeWhere(id) → SharedPreferences 갱신. confirm 다이얼로그 (1.0.8) |
| 일괄 복원 | 선택 → 하단 "일괄 복원" | 선택 entry 모두 clearDeletedAt: true |
| 일괄 영구삭제 | 선택 → 하단 "일괄 영구삭제" | 선택 entry 모두 hard delete. confirm 다이얼로그 |

**confirm 다이얼로그**: "영구 삭제하시겠습니까? 복구할 수 없습니다." → "취소 / 영구삭제". 영구삭제만 confirm (복원은 reversible 이라 confirm X).

### 4.5 빈 휴지통 empty state

휴지통 진입 시 entry 0 개:
```
┌─────────────────────────┐
│ ← 휴지통 (0개)          │
├─────────────────────────┤
│                         │
│         🗑️              │
│   휴지통이 비어있어요    │
│   삭제한 메모는 30일간   │
│   여기 보관됩니다        │
│                         │
└─────────────────────────┘
```

다만 §4.1 의 "휴지통 entry > 0 일 때만 메뉴 표시" 룰 적용하면 빈 휴지통 진입 자체가 막힘. → empty state 는 GC 후 휴지통 화면에 머무를 때만 노출 (드물지만 보존).

### 5.1 _loadMemos 필터 추가

현재 (memo_list_screen.dart):
```dart
Future<void> _loadMemos() async {
  final memos = await MemoStorage.loadMemos();
  setState(() {
    _memos = memos; // 즐겨찾기 + 일반
    _isLoading = false;
  });
}
```

변경 옵션:

**A안 (추천)**: MemoStorage.loadMemos 가 GC + 활성만 반환. 휴지통은 별 메서드:
```dart
class MemoStorage {
  static Future<List<Memo>> loadMemos() async {
    final survived = await _gcAndLoad();
    return survived.where((m) => m.deletedAt == null).toList();
  }
  static Future<List<Memo>> loadTrash() async {
    final survived = await _gcAndLoad();
    return survived.where((m) => m.deletedAt != null).toList();
  }
}
```

**B안**: `loadMemos` 가 raw list 반환, 화면이 필터. 다른 화면(휴지통)이 동일 raw 를 다른 필터로 씀.

**추천**: A안. 화면 = view, 영속 = 데이터. 책임 분리.

### 5.2 즐겨찾기 그룹 호환

- 즐겨찾기 / 일반 그룹 구분은 `isFavorite` — `deletedAt` 와 독립
- 휴지통에 들어간 메모는 isFavorite 상관 없이 휴지통에만 표시. 복원 시 isFavorite 보존
- _onReorderFav / _onReorderNormal 알고리즘 = 활성 memos 만 보므로 변경 0

### 5.3 _deleteSelected 변경

현재 (memo_list_screen.dart, PR #23):
```dart
setState(() {
  _memos.removeWhere((m) => _selectedIds.contains(m.id));
  // ...
});
await _saveMemos();
_showDeleteUndoSnackBar(deleted);
```

변경 — hard delete → soft delete:
```dart
final now = DateTime.now();
setState(() {
  for (int i = 0; i < _memos.length; i++) {
    if (_selectedIds.contains(_memos[i].id)) {
      _memos[i] = _memos[i].copyWith(deletedAt: now);
    }
  }
  // ... 화면에서 숨김 — view 가 _memos.where(deletedAt == null) 로 그림
});
await _saveMemos();
_showDeleteUndoSnackBar(deleted); // 기존 UNDO 흐름 유지
```

### 5.4 UNDO 스낵바와의 관계

기존 UNDO 스낵바 (4초) → "실행 취소" 탭 시 `_restoreDeletedMemos`:

```dart
// 기존 (hard delete + 인덱스 복원)
for (final item in deleted) {
  _memos.insert(item.index, item.memo);
}

// 변경 — soft delete clearDeletedAt
for (final item in deleted) {
  // _memos 에는 이미 soft-deleted 상태로 있음
  final idx = _memos.indexWhere((m) => m.id == item.memo.id);
  if (idx >= 0) {
    _memos[idx] = _memos[idx].copyWith(clearDeletedAt: true);
  }
}
```

UNDO 윈도우 안에서 = soft delete 의 빠른 복구. 윈도우 지나면 = 휴지통에서 복구.

### 5.5 스와이프 단건 삭제

현재 `_deleteMemo(id)` 도 `_memos.removeWhere(id)` hard delete. 동일하게 soft delete 변경.

## §6 회귀 안전망 (구현 PR 시 동반 위젯 테스트 시나리오)

### 6.1 서비스 단위

- `Memo.toJson / fromJson` — `deletedAt: null` ↔ JSON 키 누락 round-trip
- `Memo.copyWith(clearDeletedAt: true)` → deletedAt null 화
- `Memo.copyWith(deletedAt: X)` → 새 deletedAt 설정
- `MemoStorage.loadMemos` GC — 31일 전 deletedAt 메모 자동 영구 삭제
- `MemoStorage.loadMemos` GC — 29일 전 deletedAt 메모 보존
- `MemoStorage.loadMemos` GC — deletedAt: null (활성) 메모는 항상 보존
- `MemoStorage.loadTrash` — deletedAt != null 만 반환
- `MemoStorage.loadMemos` 활성 필터 — deletedAt: null 만 반환

### 6.2 위젯 시나리오

- **soft delete 흐름**: 메모 1개 → 스와이프 삭제 → SnackBar (PR #23 회귀) + 메모는 휴지통에 있음 (loadTrash 검증)
- **UNDO 흐름**: 스와이프 삭제 → SnackBar UNDO → 메모 활성 복원 + 휴지통 비어있음
- **휴지통 진입**: 1 메모 휴지통 → overflow → "휴지통" → 휴지통 화면 → entry 표시
- **휴지통 복원**: 휴지통 entry → 복원 → 메모 활성 복귀 + 휴지통 entry 사라짐
- **휴지통 영구삭제**: 휴지통 entry → 영구삭제 → confirm 다이얼로그 → "영구삭제" → 메모 사라짐 (loadMemos + loadTrash 둘 다 비어있음)

- **GC 자동**: 30일 1초 전 메모 보존 + 30일 + 1초 메모 자동 영구 삭제 (시간 mock 필요)
- **빈 휴지통**: 휴지통 entry 0 → empty state 노출 + 메뉴 entry 자체 숨김

### 6.3 사이클 #6 reorder 회귀 안전망 패턴 재활용

- ReorderableListView 의 onReorder 콜백 직접 invoke 패턴 — 휴지통 화면도 ReorderableListView 안 쓰면 N/A
