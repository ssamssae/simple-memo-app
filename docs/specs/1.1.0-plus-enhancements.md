# 메모요 1.1.0+ enhancement roadmap

**Status**: draft · 구현 전 범위 정리
**Task**: `T-260512-05`
**Date**: 2026-06-06 KST
**Scope**: Testers Community 잔여 피드백 중 "큰 업데이트에 묶을 항목" 정리. 코드 변경 없음.

## 0. 배경

Testers Community 피드백 6건 중 빠른 기본기 항목은 1.0.x 라인에서 대부분 흡수됐다.

- ASO: `docs/store-assets/metadata.md` 로 Play/ASC 복붙용 SoT 정리.
- 스크린샷: Android 정석 재캡처 자산 반영.
- Privacy/Terms: 인앱 정책 화면 + 법적 문서 추가.
- Rate button: 설정 화면 `앱 평가하기` + `in_app_review` 반영.
- Data safety: Drive 백업/복원, 공유, UNDO, 휴지통 30일이 1.0.7+28 에 포함.

남은 장기 항목은 서로 관련이 있다. 첫 실행 안내와 Help/FAQ 는 사용자에게 "메모요가 뭘 보장하고 뭘 안 하는지" 설명하는 층이고, 다국어는 그 설명을 여러 언어로 반복 가능하게 만드는 인프라다. 따라서 이 둘은 작은 패치로 쪼개기보다 1.1.0+ 사용자 안내/언어화 트랙으로 묶는 것이 낫다.

## 1. 목표

1.1.0+ 트랙의 목표는 기능을 늘리는 것이 아니라 **메모요의 사용법과 데이터 정책을 사용자가 오해 없이 이해하게 만드는 것**이다.

성공 기준:

- 첫 실행 사용자는 30초 안에 핵심 조작 4개를 이해한다.
- 기존 사용자는 설정에서 Help/FAQ 와 첫 실행 안내를 다시 열 수 있다.
- 한국어 UI 문구가 `AppLocalizations` 로 이동할 수 있는 구조가 생긴다.
- 영어/일본어 추가가 큰 리팩터 없이 가능하다.
- 스토어/정책 문서와 앱 안 문구가 서로 모순되지 않는다.

## 2. 추천 릴리스 슬라이스

### 1.1.0 — Usage Pack

가장 먼저 사용자 안내 레이어를 넣는다. 이 단계는 다국어보다 리스크가 낮고, 현재 한국어 앱만으로도 가치가 있다.

구현 범위:

- 첫 실행 onboarding 3~4장.
- 설정 화면 `도움말` 진입점.
- 설정 화면 `처음 안내 다시 보기` 진입점.
- Help/FAQ 정적 화면.
- 인앱 피드백 보내기 진입점.

Onboarding draft:

1. **제목 없이 바로 메모**
   메모요는 첫 줄을 제목처럼 보여 주고, 본문만 쓰면 된다.
2. **중요한 메모는 별표**
   즐겨찾기는 항상 위에 모이고, 해제하면 원래 일반 목록 자리로 돌아간다.
3. **밀어서 정리하고, 끌어서 순서 변경**
   왼쪽/오른쪽 스와이프와 드래그 정렬을 짧게 보여 준다.
4. **백업·휴지통·정책은 설정에서**
   Drive 백업/복원, 휴지통 30일, 정책 문서 위치를 알려 준다.

Help/FAQ draft:

- 메모는 어디에 저장되나요?
- Drive 백업과 복원은 어떻게 쓰나요?
- 삭제한 메모는 어디로 가나요?
- 휴지통 30일이 지나면 어떻게 되나요?
- 다른 기기에서도 같은 메모를 쓰려면 어떻게 하나요?
- 별표와 정렬은 어떻게 동작하나요?
- 피드백은 어디로 보내나요?

권장 구현:

- `lib/screens/onboarding_screen.dart`
- `lib/screens/help_screen.dart`
- `SharedPreferences` key: `memoyo.onboarding.v1.seen`
- 설정의 Help/FAQ 는 새 패키지 없이 정적 Flutter 위젯으로 시작한다.
- 피드백 채널은 `url_launcher` 로 `mailto:ssamssae@naver.com?subject=메모요 피드백` 를 연다.

검증:

- 첫 설치 상태에서 onboarding 이 1회 표시된다.
- 완료 후 재실행하면 표시되지 않는다.
- 설정에서 다시 열 수 있다.
- 메모 생성/편집/삭제/백업 기존 테스트가 그대로 통과한다.

### 1.1.1 — Localization Scaffold

번역을 바로 늘리기 전에, 한국어 단일 locale 로 l10n 구조를 먼저 깐다. 큰 화면부터 순차 추출해서 회귀를 줄인다.

구현 범위:

- `flutter_localizations` 추가.
- `l10n.yaml` 추가.
- `lib/l10n/app_ko.arb` 생성.
- 앱 루트에 `localizationsDelegates`, `supportedLocales` 연결.
- 설정/도움말/onboarding 문구부터 `AppLocalizations` 로 이동.
- 테스트에서 generated localization 로딩 경로 보강.

비범위:

- 영어/일본어 번역 노출.
- 앱 내 언어 선택 UI.
- 모든 텍스트 한 번에 전수 추출.

검증:

- `flutter gen-l10n`
- `flutter analyze`
- `flutter test`
- Android/iOS debug build 중 하나 이상.

### 1.1.2 — English/Japanese Translation

한국어 scaffold 가 안정화된 뒤 영어/일본어 번역을 추가한다.

구현 범위:

- `app_en.arb`, `app_ja.arb`.
- 스토어 metadata 의 영문/일문 초안과 앱 문구 톤 맞춤.
- 설정에 `언어` 항목을 추가할지 결정.

권장 결정:

- 1차는 시스템 locale 추종.
- 앱 내 언어 선택은 1.1.3 이후로 미룬다. 직접 선택 UI 는 저장값, 테스트 매트릭스, CS 설명이 늘어난다.

검증:

- 한국어/영어/일본어 snapshot 또는 widget smoke.
- 긴 일본어 문구가 버튼/타일에서 잘리지 않는지 확인.
- 스토어 설명과 앱 안 데이터 정책 문구 불일치 없음.

### 1.2.x — Sync / Advanced Data Layer

다기기 동기화는 1.1.0 usage/l10n 과 섞지 않는다. 기존 리서치 문서를 별도 메이저 트랙으로 유지한다.

참조:

- `docs/research/2026-05-21-memoyo-1.1.x-multidevice-sync-research.md`
- `docs/research/2026-05-21-memoyo-tombstone-trash-unified-schema.md`
- `docs/research/2026-05-21-memoyo-decision-brief.md`

이유:

- 동기화는 UX 문구가 아니라 데이터 일관성 기능이다.
- Drive/iCloud 백엔드, tombstone, 충돌 정책, 자동 pull/push ack 가 필요하다.
- 1.1.0 안내 문구에서 "현재는 백업/복원 방식"임을 명확히 쓰면 오히려 sync 도입 전 CS 를 줄인다.

## 3. 현재 코드 기준 영향 범위

현 상태:

- `pubspec.yaml` 에 `flutter_localizations` 없음.
- `lib/` 화면 문구는 대부분 한국어 하드코딩.
- `settings_screen.dart` 에 설정 진입점이 이미 있으므로 Help/FAQ, onboarding replay 를 붙이기 쉽다.
- `policy_screen.dart` 는 markdown-like asset 렌더 흐름이 있어 Help 화면 구현 참고가 가능하다.
- `Memo.deletedAt` 과 휴지통 30일은 이미 들어와 Help/FAQ 에 설명할 수 있다.
- Drive 백업/복원도 설정 화면 안에 들어와 있어 onboarding 4번째 장과 연결 가능하다.

추정 리스크:

- l10n big-bang 추출은 테스트·문구 누락·레이아웃 깨짐 위험이 크다.
- generated file 누락으로 CI/analyze 가 깨질 수 있다. `flutter gen-l10n` 절차를 문서화해야 한다.
- 일본어는 문장 길이와 line break 가 달라 설정 타일/버튼 overflow 검증이 필요하다.

## 4. 사용자 문구 원칙

- "자동 동기화"라는 말을 1.1.0 에서 쓰지 않는다. 현재는 백업/복원이다.
- "Google Drive에 저장"은 "사용자 본인 Google Drive의 Memoyo 폴더"로 설명한다.
- 휴지통은 "30일 후 자동 영구 삭제"를 명시한다.
- 개인정보는 "메모 내용은 개발자 서버로 전송되지 않음"을 반복한다.
- 도움말은 마케팅 문구가 아니라 문제 해결 문구로 쓴다.

## 7. Non-goals

- 1.1.0 에 sync 구현을 끼우지 않는다.
- Help/FAQ 를 원격 CMS 로 만들지 않는다.
- 앱 내 언어 선택을 l10n scaffold 와 같은 PR 에 넣지 않는다.
- 온보딩을 매 실행마다 띄우지 않는다.
- 사용자의 메모 내용을 샘플/가이드에 재사용하지 않는다.
