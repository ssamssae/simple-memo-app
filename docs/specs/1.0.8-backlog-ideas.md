## 1. 휴지통 30일 (1.0.7 (4) carry — 최우선 후보)

**What**: 삭제된 메모를 30일간 `Memo.deletedAt != null` 소프트 delete 로 별 "휴지통" 화면에 보관. 30일 경과 자동 영구 삭제 + 사용자가 휴지통에서 "영구 삭제 / 복원" 선택.

**Why**:
- 1.0.7 (2) UNDO 스낵바는 4초 윈도우만 — 폰 잠그고 다시 와서 후회 시점에는 이미 사라짐
- 1.0.7 (1) Drive 백업은 회전 7개 — 백업 사이 시점 메모 손실 가능
- 휴지통 30일이 UNDO + 백업 사이의 **장기 안전망**
- 형님 발화 출처: [[1.0.7-data-safety-ux.md]] §0 4 항목 묶음 마스터

**Cost**:
- 데이터 모델: `Memo` 에 `deletedAt: DateTime?` 추가. 기존 메모 마이그레이션 = `deletedAt: null`.
- 저장 레이어: `MemoStorage` 가 `deletedAt != null` 필터링하여 목록에서 숨김. 휴지통 화면은 반대 필터.
- 보존 GC: 앱 cold start 시 `now - deletedAt > 30 days` 메모 영구 삭제. 백그라운드 작업 X (배터리/iOS bg task 복잡도 회피).
- UI: 휴지통 화면 1개 신설 (목록 + "복원" / "영구삭제" 액션). overflow 메뉴에 "휴지통" entry.
- Drive 백업 호환: `deletedAt != null` 도 백업 JSON 에 포함 (가져오기 시 휴지통 상태 보존). 또는 백업은 활성 메모만 — 형님 결정 필요.

**Open**:
- (a) Drive 백업에 휴지통 포함 vs 활성만 — 백업 크기 vs CS 안전 trade-off
- (b) 30일 vs 14일 vs 90일 — iOS Photos/Notes 는 30일, Gmail 은 30일 (휴지통). 30일 디폴트 + 사용자 변경 X
- (c) 휴지통 화면 진입 위치 — overflow 메뉴만 vs 편집 모드에서도 진입 가능

## 2. 메모 태그 / 카테고리

**What**: 메모에 자유 태그 (`#일`, `#책`, `#아이디어`) 추가. 목록 상단에서 태그 필터.

**Why**:
- 즐겨찾기 vs 일반 2 그룹은 메모 100개 넘어가면 부족 — 카테고리 필요해짐
- 본인 dogfood: 강대종이 쓰면서 "이 메모 책 관련" / "이 메모 일 관련" 자연스럽게 라벨
- 사용자 요청 빈도가 결정 변수 — 현재 0건이면 후순위

**Cost**:
- 데이터 모델: `Memo.tags: List<String>` (디폴트 빈 리스트, 마이그레이션 호환)
- 입력 UX: 편집 화면 본문 위 또는 아래 태그 입력 칩 (자동완성 — 기존 태그 set)
- 목록 UX: 상단 가로 스크롤 칩 (전체 / 즐겨찾기 / 태그별), 또는 검색 UX 와 통합

**Open**:
- (a) 자유 태그 vs 고정 카테고리 (4~5개 미리 정의) — 자유 태그가 dogfood 친화, 고정은 단순함
- (b) 태그 색상 — 자동 hash 색상 vs 사용자 지정
- (c) 검색 (§3) 과 묶을지 분리할지

## 3. 검색

**What**: 목록 상단 검색바 → 메모 본문 / 태그 부분 매칭. 결과는 필터된 목록.

**Why**:
- 메모 200개 넘어가면 스크롤 한계 — 검색 필수
- iOS Notes / Google Keep 디폴트 — 사용자 학습 곡선 0
- 본인 dogfood: "그 메모 어디 있더라" 빈도가 결정 변수

**Cost**:
- UI: AppBar 토글 → 검색바 (또는 목록 상단 고정 SearchBar). 결과 인라인 필터.
- 인덱싱: 메모 500개 이하면 in-memory linear scan 으로 충분. 그 이상 시 lazy index (별 사이클).
- 매칭: 한글 자소 분리 X (디폴트 substring contains). 영어 case-insensitive.

**Open**:
- (a) 검색 결과 정렬 — 매치 위치 (제목 후보 = 첫 줄) > 본문 > 태그 vs 단순 updated_at
- (b) 검색어 하이라이트 — 결과 메모 카드에 일치 부분 노란색 vs 단순 필터만
- (c) 빈 검색어 → 전체 목록 즉시 복귀 (디바운스 0)

## 4. 메모 별 폰트 크기 / 줄간격 (저우선)

**What**: 메모 작성/편집 화면에 폰트 크기 + 줄간격 슬라이더. 시스템 다이내믹 타입과 별개 메모요 디폴트.

**Why**:
- 본인 dogfood 이슈: 현재 fontSize 18 + 줄간격 1.5 가 폰 가로/세로 모드에서 가독성 차이
- iOS 시스템 다이내믹 타입은 모든 텍스트 일률 — 메모요만 커스텀 필요한 사용자 niche

**Cost**:
- 설정 화면 1개 신설 (없으면). overflow → "설정" entry
- 본문 TextField 의 `fontSize` / `height` 만 동적 — 코드 영향 최소

**Open**:
- (a) 설정 화면 신설 비용 vs 1.0.8 scope creep
- (b) 사용자 요청 빈도 0 이면 후순위 후보

## 5. iCloud / Google 다기기 sync (1.1.x 후보, 1.0.8 비추)

**What**: Drive 백업/가져오기 1버튼 위에 **자동 sync** — 메모 작성/수정 시 백그라운드 Drive 푸시, 다른 폰 진입 시 자동 풀.

**Why**:
- 1.0.7 (1) Drive 백업은 수동 1버튼 — 다기기 사용자는 매번 수동 백업/가져오기
- 사용자가 iPhone + iPad 또는 Galaxy + 갤럭시탭 묶음 사용 시 자연 요구

**Cost**:
- 비용 폭발 — 충돌 해결 / 동시 편집 / 오프라인 큐 / 트래픽 / Drive API quota. 1.0.7 대비 1주 vs 1달 차원
- 1.1.x 메이저 — 1.0.8 scope 아님. 출처: [[../research]] 1.1.x 다기기 동기화 사전 리서치 (PR #16)

**Open**:
- (a) 1.0.8 비추 명시 — 휴지통 (§1) + 검색 (§3) 묶음으로 1.0.8 정의
- (b) 1.1.x 메이저 진입 전 1.0.7 GA + 1.0.8 사용자 피드백 1~2달 모니터링 후
